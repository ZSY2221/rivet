# RIVET: Cross-Stage Integrity for Verifiable Federated Aggregation

## Environment

- Windows 11 or Ubuntu 22.04
- Python 3.10, 3.11, or 3.12 (`python3-venv` on Ubuntu)
- Rust 1.83.0 and Cargo
- Windows Rust builds require Visual Studio Build Tools with the Desktop C++ workload
- Intel Core i7-13700, 24 threads, 32 GB RAM for timing measurements
- MP-SPDZ commit `6a2256e327b507918859f605735543bb32a39d9d`
- libOTe commit `1264725c3f08c2acaed70b2f3f67a68f38c53012`

## Install

Windows PowerShell:

```powershell
./scripts/setup_windows.ps1
```

Ubuntu:

```bash
chmod +x scripts/*.sh mpc/*.sh
./scripts/setup_linux.sh
```

## Training

The complete paper configuration uses MNIST (100 rounds), CIFAR-10 (50
rounds), IID and Dirichlet partitions (`alpha=0.1,0.5`), FedAvg and RIVET,
four seeds, malicious fractions `0,0.1,0.2,0.3`, 20x norm inflation and
20-coordinate gradient concentration.

Windows:

```powershell
./scripts/run_training.ps1
```

Ubuntu:

```bash
./scripts/run_training.sh
```

Datasets download to `data/`. Results are written to
`results/training_results.csv`.

## Scope

This repository publishes the RIVET implementation and its measurement scripts. Comparison numbers for published schemes in the paper are taken from their respective public designs; their reproduction code is outside the scope of this repository.

The `training/` path is a floating-point simulator that evaluates the statistical effect of the screening predicates and produces the paper's accuracy results. Fixed-point quantization and the per-coordinate `[-B, B]` range check specified by the protocol are implemented in `mpc/rivet_screen.mpc` and included in the MP-SPDZ measurements. The `s`, `C`, and `B` values in `configs/params.toml` are protocol-path parameters and are not used by the training simulator.

The `mpc/rivet_screen.mpc` program is a gate-count and communication-cost benchmark. Its inputs are constants and its thresholds are placeholders, so it measures circuit cost rather than functional correctness. Its gate structure follows the cost accounting in Section 4 of the paper: each client update uses `2d+1` comparisons, `d` Beaver multiplications, and `L` sketch comparisons. Sketch projections are linear operations and produce no communication in SPDZ, so they do not affect the measured benchmark cost.

The `results/` and `figures/` directories are generated at runtime; training result files are not included in the repository.
